clinical-intelligence

Technical assignment Senior Backend & Platform Engineer Rutik Pol Ten monographs Download PDF

Architecture, retrieval and evidence provenance for a physician-facing platform — and a plan for taking ownership of one somebody else already built. Every number below is either derived from the brief or cited; where I am guessing, it says so.

The volumes are a misdirection

20,000 queries a day is 0.23 QPS — three warm pods. Ten million documents is ~300M chunks, which is past every pgvector ceiling ever measured. Sizing the API for the query count is the mistake the brief invites.

The model never writes the number

The LLM turns retrieved passages into typed, cited statements. A deterministic gate checks every dose and threshold appears literally in its cited span. Composition is code. The model is an extractor, not an oracle.

Silence is not a recommendation

"No guideline addresses this", "guidelines recommend against", and "retrieval failed" are three different states and must never render alike. Conflating them is the failure mode that reaches a patient.

Monograph 01 · Platform

End-to-End Architecture

Read it in three moves. Left of the gate the system is reducing; at the gate it is verifying; right of the gate it is deterministic. Nothing enters the store whose evidence cannot be pointed at.

Ingestion and query share nothing but the store. Ingestion is a restartable batch job on spot capacity that can fall a day behind unnoticed; query is synchronous and latency-budgeted. Coupling them turns a parsing backlog into an answer-latency incident, which is the first thing I would check in the inherited system.

No third party sits on the request path. Workers poll sources and model APIs on their own schedule and write to Postgres; the API only reads. A throttled upstream degrades freshness, which the response reports, rather than returning an error to a physician mid-consultation.

ChoiceWhyWhat it costs
Modular monolith API, separate worker and ingestion fleetsThree deployables. At 0.23 QPS, service decomposition buys nothing and costs distributed transactions and on-call surface.Module boundaries need enforcing in review; nothing physically prevents a cross-import.

Scaling order when it is needed: workers scale horizontally first because they are stateless, then Postgres gains read replicas, then the vector index moves out. Not the reverse.

Monograph 02 · Corpus

Ingestion, Two Clocks & Versioning

You can always recover when a guideline was published. You can never recover when you learned it. That is one column now, or an honest audit trail never.

Every row carries effective_time (when the recommendation is in force) and ingest_time (when we indexed it), and every query names which it means. status = 'current' is not a flag anyone maintains — it is a materialised view over those two axes. This is what makes the assignment's own scenario work, and it is also what answers "what did the guideline say when I treated this patient in March 2026", which is a medico-legal question and not a feature request.

MechanismDetail
Bitemporal constraintEXCLUDE USING gist (work_key WITH =, effective_range WITH &&, asserted_range WITH &&) — range types rather than an extension, because no maintained bitemporal Postgres extension exists and this is the most correctness-critical table in the system.
Append-onlyNever UPDATE. A revision is a new row. Composite B-tree (work_key, ingest_time DESC) serves both the as_of filter and latest-version-per-work.
Supersession is per sectionA 2027 edition commonly replaces some chapters and leaves others standing. Whole-document supersession silently deletes still-current paediatric guidance the new edition never touched.
Snapshot at ingestPublishers silently revise. Without a snapshot, a citation resolves against text that did not exist at the timestamp it claims.

Multimodal: fuse at the statement, never at the tensor

The reflex is to embed prose, dosing tables and figures into one latent space. Wrong level, for three checkable reasons: they have incompatible revision policies, a joint embedding is unauditable, and the evidence pointer each needs is structurally different. The level at which they are commensurable is the statement — every modality is a sensor emitting a typed clinical assertion with a pointer back to its own evidence.

ModalityEvidence pointerWhy it is not prose
Guideline prosechar_start / char_end into the snapshotThe default case, and the only one most pipelines handle.
Dosing / eligibility tabletable id + row/column coordinates + header pathA cell means nothing without its row and column headers. Linearising a table into prose destroys exactly the structure that carries the instruction.
Figure, algorithm, flowchartpage + bounding box + caption + extracted nodesTreatment algorithms are frequently only in the figure. Caption-only indexing silently drops them.
Structured reference
formulary, drug database		record id + versionAlready typed. Embedding it is strictly worse than joining to it.
The one I would spend review budget on

Tables are a patient-safety surface, not a parsing nicety. A dosing table is where the clinical instruction actually lives, and a mis-parsed cell turns an eGFR threshold into a dose. Table extraction carries its own confidence score; below threshold it is quarantined for human review rather than indexed. Parsing is tiered — JATS/NLM XML parsed directly where it exists (structure is free, prefer it whenever the same content exists twice), HTML by readability extraction, text-layer PDF via PyMuPDF with coordinates, and only scanned or complex layouts routed to the expensive layout model.

Chunking, and what not to do to it

  • Not everything is chunked. A recommendation is not local — the population it applies to is often three paragraphs above the sentence stating the dose. Chunk long guidelines and reviews; leave short documents whole.
  • Split on structural boundaries, never fixed token counts. Never separate a number from its unit or subject, never split a table, never separate a recommendation from its evidence grade. Carry the document header into every chunk and store char_offset back into the snapshot.
  • No summarisation before indexing. The gate verifies verbatim spans; a summary leaves nothing to check. Contextual retrieval prepends a blurb and never replaces the chunk — that is what cuts top-20 retrieval failure roughly 5.7% → 3.7%, and to ~2.9% with contextual BM25.
  • Dedup at two levels. Exact by normalised hash and identifier (DOI, PMID); near-duplicate by MinHash over shingles. The same guideline routinely arrives as publisher PDF, PubMed XML and society HTML. Keep the alternates as manifestations — the PDF is what a physician wants opened at the cited page.
  • Version the embedding model per chunk. Migration is dual-write into a second index and an atomic alias flip, never in-place.
Monograph 03 · Retrieval

Hybrid Search — and the Three Jobs That Are Not Search

Only one of the four retrieval jobs this platform performs is actually a search problem. Solving the other three with vectors is the most common and most expensive mistake available here.

JobWhat it actually isWhy not vector search
Duplicate guideline detectionMinHash / SimHash + LSHCosine similarity conflates "same recommendation restated" with "related but clinically distinct" — precisely the boundary that must stay sharp. And a reranker actively harms this job: it ranks the duplicate highest, which is exactly backwards.
Drug and condition normalisationRecord linkage — RxNorm / SNOMED alias tables + fuzzy matchResolves most mentions in microseconds and deterministically. Embeddings are fallback candidate generation only, never auto-accept, and every resolution writes back to the alias table.
"What have we answered before"A WHERE clause on (entity_id, time_range)Not retrieval at all.
Cross-guideline evidence assemblyThe only genuine hybrid search—

For that one real job, hybrid is insurance against disjoint failure modes, not a silver bullet. Dense retrieval collapses on rare tokens — SGLT2, NT-proBNP, eGFR <30, a specific drug name, an ICD code — which are exactly what a physician types. BM25 cannot connect "kidney impairment" to "renal insufficiency". Fuse with RRF (k=60) rather than weighted scores, because BM25 and cosine are on incomparable scales and any fixed blend weight silently stops being right as the corpus grows. Move to a tuned combination only once accept/reject decisions have supplied a label set.

The pgvector cliff is a RAM cliff, and it is invisible in the metric people watch

Published measurement on a 32 GB box at 1536 dims: QPS held near 2,100 out to 2M vectors, fell ~45% at 2.5M when the index passed shared_buffers, and collapsed ~95% by 3M — to about 102 QPS — while the buffer hit ratio stayed above 98%. Nothing looked wrong on the dashboard. Practical ceiling is roughly 10M vectors provisioned properly, ~3M if not: halfvec, shared_buffers sized above the index, and dimension truncation (512 dims retains ~94–96% of NDCG@10).

At ~300M chunks, pgvector is not a close call. My earlier instinct was to name a 50M-chunk trigger; the measured evidence puts the ceiling an order of magnitude lower, so this is a when, not an if. Start on pgvector because it is almost certainly what exists and it is correct for a pilot corpus, keep retrieval behind one interface, and plan the move to OpenSearch or Qdrant as scheduled work rather than an emergency.

Filtered vector search degrades far worse than intuition suggests, and our filters are the bad case. A single broad filter drops recall to about 90.8%; an AND over two broad values to about 39.7%. Pre-filtering fragments the HNSW graph; post-filtering silently returns too few. Every query here carries tenant, effective status, specialty and population filters simultaneously — so this is the normal case, not the edge case. pgvector 0.8+ iterative index scans are load-bearing, and this is the single strongest argument for an engine that treats filtered ANN as a first-class problem.

Embedding choice is constrained before it is optimised. If the corpus is multilingual the biomedical-tuned embedders mostly are not, and coverage beats domain lift — take the domain lift from a downstream reranker instead. Metadata that earns its place: char_start/char_end (what makes "embed raw text" usable by the gate), primary_source_id (Monograph 05), the two clocks, entity_ids[], observation_status, and the lineage quartet trace_id / prompt_version / extractor_version / embedding_model_version.

Monograph 04 · Generation

RAG, and Where Agents Are Forced to Stop

The criterion is not "is this complex" but "is the step count knowable in advance". Almost all of this pipeline's steps are, and pretending otherwise buys a planner nobody can test.

"How should treatment differ for a patient with heart failure, CKD and type 2 diabetes according to current guidelines?" is not one retrieval. Three guideline bodies each address one condition and the clinically interesting content is where they modify each other — agents indicated across all three, dosing that changes with renal function, monitoring one introduces that another never mentions. But the shape of that work is known in advance, so it is a workflow with a bounded planner, not an agent.

Two jobs genuinely warrant agency, because their step count is unknowable: hunting corroborating primary evidence, and resolving a contradiction between two guideline bodies. Both get a hard step budget, a wall-clock cap, and partial results rather than a loop. Three terminal states — resolved, contradicted, and unresolved as a first-class result that lowers confidence rather than retrying. Every tool either holds is read or search only: no write, no send.

Fan out by lens, not by volume. Three agents asking the same question produce correlated agreement that reads as confirmation. Three with different remits produce information.

Patterns I would decline, and why

DeclinedEvidence
Free-form agent loop on the clinical pathUntestable — no regression suite exists for a control flow that differs per run, so quality becomes unmeasurable exactly where it matters most. Reproducibility is also medico-legal: the same question twice must not yield materially different guidance.
Chain-of-thought on extractionGains are near-exclusive to maths and symbolic tasks, negligible or negative elsewhere, and it fights constrained decoding.
An LLM critic instead of a deterministic verifierIntrinsic self-correction fails and sometimes degrades; it works only with reliable external feedback. The grounding gate is that feedback.

Schema-constrained decoding is the exception that helps on both axes — it improves quality and speeds generation. The widely cited "structure hurts reasoning" result ran its structured arm as naive JSON mode with no schema.

Monograph 05 · Evidence

Provenance, the Grounding Gate & Silence

The referee is deterministic and it is the most important component in the system. A check that cannot fail is worse than no check, because it reports as passing.

When the model emits a statement it emits the passage IDs that statement came from, drawn from the closed set placed in its context. Those IDs are foreign keys, so rendering a citation is a join — a citation cannot disagree with its evidence, and an invented ID fails immediately because it does not exist. The chain is document → version → section(page, char_span) → passage → statement → citation, stored, never reconstructed.

GateRuleCost
1 · Retrieval floorIf the best reranked passage is below threshold, generation never runs.One comparison.
2 · Closed-set IDsA passage ID absent from the context is a hard failure, not a warning.A set membership test.
3 · Numeric groundingA statement carrying a dose, threshold, age cutoff or interval is rejected unless that figure appears literally in its cited span, NFKC-normalised. Resolved against the snapshot, never the chunk.String matching. This is the control that matters most, because numbers are what reach the patient.
4 · EffectivenessEvery cited section must still be in force at the query's as_of, or the answer carries an explicit staleness notice.Already in the join.
5 · EntailmentNon-numeric claims checked against their own cited passages by an NLI or small judge model.One small-model call per statement — the only gate with real cost.

Every rejection is a free labelled failure and goes straight to the golden set. That is the cheapest, most mechanical and most immediate label source the architecture produces, and it costs nothing to collect.

Absence has four meanings and they must never render alike

Every statement carries an observation status, because conflating these is the failure mode that reaches a patient:

  • recommended — a guideline affirmatively says to do it.
  • recommended_against — a guideline explicitly advises against it. This is evidence.
  • not_addressed — no current guideline covers this combination. This is not evidence of anything, and it is the common case for genuinely multi-morbid patients.
  • degraded — parsing or retrieval failed. We do not know. This must never be presented as either of the two above.

An unmeasured axis widens the confidence interval rather than narrowing it. A system that answers confidently because it retrieved nothing has inverted the meaning of its own silence.

Corroboration must be counted at the primary-evidence level. Three review articles citing the same trial are one piece of evidence repeated cheaply, and text similarity returns exactly those copies first. Two guidelines agreeing because both cite the same RCT is echo, not independent support. So every passage carries a primary_source_id derived from the citation graph, and corroboration counts distinct primary sources — never distinct documents. Without it, confidence rises with citation volume, which is the opposite of what it should track.

When evidence is insufficient the system abstains, returning the closest evidence found and stating plainly that no current guideline addresses the combination. Abstention rate is a tracked metric; a rise on a topic is the clearest available signal of a corpus gap and routes to the content team, not to on-call. When evidence conflicts, do not resolve it — surface it. Present both positions attributed by issuing body, date and evidence grade, and name the axis of disagreement. Physicians are trained to weigh conflicting evidence; silently picking a winner is the worst available behaviour precisely because it is invisible.

Monograph 06 · Platform

Core Backend & Multi-Tenancy

Row-level security handles the relational data. The vector index is the part it does not cover, and that is where tenant isolation is actually decided.

Three deployables: a FastAPI application, a worker fleet on Celery or ARQ over Redis and SQS, and the ingestion pipeline on Airflow. Core schema is tenant, user, membership, role, the bitemporal corpus chain from Monograph 02, then query, answer, statement, citation, feedback, audit_event, ingestion_job.

Data classModelWhy
Tenant operational dataShared schema, Postgres row-level securityEnforced by the database, so an ORM mistake or a forgotten WHERE cannot leak. Application-level scoping is one missing clause from an incident.
Public medical literatureOne shared corpusThe guideline is identical for every customer. Duplicating ~300M chunks per tenant is indefensible on cost and multiplies every re-embedding job by the customer count.
Tenant-private protocols and formulariesPhysically separate collectionNot a filter column. For data whose leakage would end the company, physical separation beats a predicate one code path can forget.
Three inherited defects I would grep for in week one

RLS does not protect the vector index. An ANN search is not a row scan; a retrieval path that forgets its tenant filter returns another hospital's protocol with no database-level objection. So no caller builds a search directly — one retrieval function applies the predicate, with a test asserting a cross-tenant query returns zero rows.

PgBouncer in transaction mode breaks session-scoped RLS. Setting app.tenant_id once per connection leaks silently across pooled sessions; it must be SET LOCAL inside the request transaction.

Prompt injection through ingested documents. Third-party medical PDFs are attacker-influenceable input. If the extraction or answer path holds any tool that can write, send or call out, that is a live injection chain. Extraction is structured-output-only with no tools.

  • OIDC and SAML per tenant — hospitals arrive with Entra ID or Okta and will not create separate accounts. SCIM for provisioning and, more importantly, deprovisioning.
  • Roles: physician, librarian (curates the tenant corpus), tenant admin, auditor (read-only, no clinical authoring). Enforced at the service boundary, never in the UI.
  • Append-only audit log in its own table with no update or delete grant — every query, answer, citation, corpus change and access grant, each carrying the lineage quartet. A compliance requirement, and the only thing that makes an answer from six weeks ago explainable.
  • Redis holds sessions, rate limits, idempotency keys, the query-embedding cache and reranker results. Not final answers — Monograph 08 covers why.
  • No conversational memory store. The evidence table is already durable and bitemporal; a vector "memory" would be a second, unversioned copy of facts that already have point-in-time semantics.
Monograph 07 · Scale

Cloud, Bottlenecks & Four Planes of Monitoring

Sub-second reads are a database index, not an achievement. The SLO that matters is that a physician can always distinguish "no guidance exists" from "our pipeline stalled".

StatedDerivedConsequence
20,000 queries / day0.23 QPS mean · 2–4 peakThree warm pods. Serving capacity is not a design constraint, and sizing for it is the misdirection.
100,000 physicians~5,000 weekly activeA user-table problem, not a load problem.
10,000,000 documents~300M chunks · ~1.2 TB fp32The actual scale problem. Past every measured pgvector ceiling; sets engine, memory and quantization.
Concurrent ingestion pipelines~42 h full re-embedAn embedding upgrade is planned dual-write work, not a background task.

Bottlenecks in the order they bite: PDF and table parsing throughput (slowest, most failure-prone, sets corpus growth rate); filtered-ANN recall at 300M vectors (degrades invisibly — only a golden set catches it); LLM time-to-first-token (dominates p95 once retrieval is tuned); cross-encoder reranking (200–600 ms on CPU, fine at 4 QPS); Postgres connections (async workers plus an async API exhaust the pool long before the CPU — PgBouncer from the start).

EKS for API and workers, because Docker is already the unit and pipeline stages are long-running in a way Lambda's execution ceiling and cold starts actively fight; serverless is right for the event glue and wrong for the pipeline. Karpenter for nodes, KEDA scaling workers on queue depth rather than CPU, since queue depth is what correlates with backlog. Ingestion runs on spot — idempotent, checkpointed and restartable makes it close to an ideal spot workload. RDS Multi-AZ, ElastiCache, object storage with versioning and Object Lock, Terraform for everything including the click-ops inventory the takeover audit turns up.

The lineage no vendor supplies is trace → statement → answer → physician verdict six weeks later. Every statement row carries trace_id and the version quartet, or "the answers got worse in March" is unanswerable. Freshness honesty: 100% of responses carry the effective dates of the evidence behind them, so zero staleness is silent.

Continuous ablation, and the degradation order

Monthly, pull each component — reranker, query expansion, the corroboration step — and measure both sides. The resulting marginal-value-per-dollar table doubles as the documented degradation order when a budget governor or an incident forces shedding. Deciding what to switch off during the incident is how you switch off the wrong thing.

Disaster recovery has an asymmetry worth stating. Postgres restores by PITR in minutes; the index does not, because the expensive work is parsing and embedding rather than storage. RPO and RTO therefore differ by data class — minutes for operational data, and for the index either an accepted multi-day RTO or a warm cross-region replica, depending on what the enterprise contracts actually commit to. A backup is real only once a restore has been performed.

Monograph 08 · Economics

AI Cost & Performance

Self-hosting is a pricing-floor problem, not a utilisation problem. What eventually forces a dedicated deployment is capacity or compliance — almost never cost.

WorkloadChoiceWhyShare of spend
Query understanding, planning, validationHosted small model, unbatchedIt gates the interactive path, so latency matters. Pricing this tier at a frontier model is where budgets die.< 10%
Answer generationHosted frontier, streamedCorrectness-critical and physician-facing.~90%
Ingestion extractionHosted mid-tier, batched into 15–30 min windowsBatching is what makes prompt caching pay: outside the cache TTL every call is a fresh write at ~1.25× that no later read amortises.one-time + delta
EmbeddingsHosted, batch the backfillThe 300M-chunk backfill is a scheduled project with a known price, not a running cost.one-time

At roughly 8k input and 800 output tokens per answer on a frontier model, 20,000 queries a day is on the order of $700–800/day, ~$23k/month, of which generation input context is about two thirds. Every optimisation worth doing early follows from that one fact — and each is also a quality improvement, which is why they come first.

  1. Context tightening. Reranking hard to 6–8 passages rather than 20 halves input cost, cuts TTFT, and improves answers, because a model given twenty passages attends worse than one given eight.
  2. Route by stage. Understanding, planning and validation do not need a frontier model — most calls by count, a small share of spend once routed.
  3. Cache the retrieval layer, not the answer. Query-to-embedding is an exact-match cache with a high hit rate; reranker results likewise.
  4. Stream. Perceived latency is TTFT, not total.
  5. Move non-interactive work off the request path — batch reviews and digests are queued jobs with a notification.
One optimisation I would refuse outright

No semantic caching of final answers. Two clinically distinct questions can sit close enough in embedding space to register as a hit — a paediatric and an adult dosing question, or the same question with and without a contraindication. Serving one for the other is a patient-safety failure disguised as a latency improvement. Exact-match caching on a normalised query, scoped to corpus version and invalidated when it changes, is the safe form and where I would stop.

The golden set is three sets, and the cheapest one matters most

Gold-A — grounding: does the statement reflect its cited passage? Needs no clinical knowledge, the gate adjudicates much of it mechanically, and it is where most real defects live. Gold-B — retrieval: was the right evidence found at all? Gold-C — clinical correctness: needs physicians, stays small, and is a falsification set rather than a training set — a couple of hundred cases is enough to reject a change, never enough to fit one. Two ordering rules are load-bearing: dedup before splitting (or the same guideline lands in both halves), and split by time.

What may learn, and what never may. Retrieval weighting, query expansion, the alias table and calibration may all be tuned. The grounding gate, the two clocks and the abstention threshold never learn — a referee that learns can learn to pass what it should fail, and then every metric improves while the system gets worse.

Five areas audited first

  1. Tenant isolation and PHI Is the vector search actually filtered by tenant or only the SQL? Is RLS enabled, and does connection pooling defeat it? Does any log, trace or prompt carry PHI? Is every third-party processor covered by a BAA? One cross-tenant leak is existential.
  2. Is there a real grounding check, and can it fail? The specific thing to look for is a verifier that cannot return false — a guard short-circuited to True, a threshold set to zero, a check wrapped in a bare except. This is not hypothetical; it is the most common way a safety control is present in the code, cited in the docs, and absent in effect.
  3. Durability and the rebuild path Are raw sources retained immutably, and can the index be rebuilt from them? Has anyone tried? If the vector store holds the only parsed copy, that is a company-ending single point no backup schedule addresses.
  4. Retrieval and answer quality — the silent one Most likely there is no eval set, so quality is unknown rather than good. I would read the actual retrieved passages for fifty real queries. Least likely to be on the partner's own list.
  5. Secrets, IAM, deploy and rollback Credentials in the repository, over-broad roles, public endpoints. And: can we deploy without the partner, is there a rollback, are migrations reversible? If deployment runs through a person at another company, ownership has not transferred whatever the contract says.

Three decisions with no single correct answer

1 · pgvector, or a dedicated engine — and when

Not whether — the measured ceilings settle that at 300M chunks — but when to spend the migration. Staying costs recall degrading invisibly under exactly the multi-filter queries this product issues; moving early costs a second source of truth before there is a corpus needing one.

Position nowStart on pgvector — almost certainly what exists, and correct for a pilot corpus — with retrieval behind one interface and recall@20 measured continuously under production filters. Migrate on the measurement, not the calendar. I would rather be six weeks late to OpenSearch with a number than six months early on a hunch.
2 · How much of the answer the model is allowed to write

Fully generative reads better and handles the long tail. Extract-then-compose — the model emits typed cited statements and code assembles the answer — is auditable, testable and lets the gate check every number, at the cost of a stiffer answer and real work in the composition layer.

Position nowExtract-then-compose, because it is the only version where "which evidence produced this sentence" has an answer that is not itself a model output. This is the decision I would most want to revisit with physicians in the room — if the composed answer reads as unusable to a clinician, the constraint has to move, and I would rather learn that in week three than defend it for a year.
3 · Shared corpus, or per-tenant isolation

Shared costs a fraction of the storage and embedding, one re-embedding job, one quality bar — but every isolation bug is a cross-tenant bug. Per-tenant is trivially auditable and easy to sell into a hospital security review, at hundreds of times the index cost and a fleet operation per model upgrade.

Position nowHybrid, split by data class. Public literature is identical for everyone and belongs in one shared corpus; tenant-private protocols go in a physically separate collection, not a filter column. Full physical isolation stays a priced enterprise tier, so the answer to a demanding security review is commercial rather than architectural.

And what I would deliberately not build: streaming infrastructure, a dedicated vector database on day one, a feature store, a fine-tuned extractor, multi-agent debate, conversational memory, or self-hosted inference. Every one has a stated trigger in Monographs 03, 04 and 08. Adopting them earlier buys operational surface to solve problems this system does not have, which is the most common way a small platform team stops shipping.
